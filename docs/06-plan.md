# 实施计划、风险与验收标准

## 1. 分阶段计划

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| P0 环境与规划 | 环境核查、数据库实例、Maven、文档 | 文档齐备，数据库可连接 |
| P1 骨架 | 后端多模块、Flyway、统一响应/异常、JWT、RBAC、前端脚手架 | 登录成功、权限菜单正确、构建通过 |
| P2 系统与基础资料 | 用户/角色/菜单/部门/字典/日志；商品/分类/单位/客户/供应商/仓库 | 各页面 CRUD 可用，权限生效 |
| P3 库存 | 余额/流水/出入库/调拨/盘点/冻结/预留/预警 | 库存变动生成流水，余额可核对，并发不超卖 |
| P4 采购 | 采购订单/审批/收货/入库/应付 | 分批收货正确，重复收货被拦截 |
| P5 销售 | 销售订单/审批/发货/出库/应收 | 分批发货正确，库存不足被拦截 |
| P6 财务 | 收付款/核销/账龄/账户 | 核销后余额正确，超额核销被拦截 |
| P7 审批/CRM/报表 | 审批中心、CRM、仪表盘与报表导出 | 审批回写状态，报表与明细一致 |
| P8 测试与交付 | 后端测试、前端 lint/build、E2E、Docker、文档 | 测试实际通过，部署可启动 |

## 2. 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 本地 MySQL 3306 密码未知 | 无法直接使用既有实例 | 已在 3307 启动独立开发实例，生产用 Docker Compose |
| Docker Desktop 未安装/守护进程未运行 | 容器化验证受限 | 提供 compose 配置并做静态校验；本地以进程方式验证 |
| 模块多、依赖复杂 | 循环依赖、构建失败 | 单向依赖；先定义接口再实现 |
| 并发库存扣减 | 超卖/重复扣减 | 行锁 + 乐观锁 + 状态机条件更新 + 并发测试 |
| 报表口径不一致 | 数据不可核对 | 报表 SQL 只读聚合业务表，提供明细钻取与核对用例 |
| 前端页面量大 | 交付周期长 | 通用组件与 API 封装复用，按模块渐进交付 |

## 3. 验收标准（必须实际验证）

1. 登录后仅能访问授权菜单与数据，未授权接口返回 403。
2. 采购订单审核 → 收货 → 入库后库存增加，流水与余额一致。
3. 销售订单审核 → 出库后库存减少，库存不足时出库失败。
4. 相同幂等键重复提交不重复扣库存/重复付款。
5. 审批驳回后单据状态不回写为已审核。
6. 收付款核销后应收/应付余额正确，超额核销被拒绝。
7. 报表统计值与业务明细汇总一致。
8. 后端 `mvn test` 全部通过；前端 `npm run lint`、`npm run build` 通过。
9. `docker compose config` 校验通过，部署文档可执行。

## 4. 验收环境

- 开发库：`jdbc:mysql://127.0.0.1:3307/erp`，账号 `erp / Erp@123456`（本机独立实例）。
- 生产示例：Docker Compose（MySQL 3306、后端 8080、前端 Nginx 80）。
